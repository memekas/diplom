# Проектная документация «Padel Tournaments» (глава 2 — Проектирование)

Этот каталог — **исходный материал для главы 2 «Проектирование»** дипломной работы.
Документы написаны по фактическому коду приложения (Next.js 16 + Prisma 6 + SQLite + Better Auth)
и предназначены для того, чтобы другие диалоги/ИИ-агенты писали по ним связный текст главы.

> **Принцип:** здесь описано, ЧТО и КАК спроектировано — назначение, архитектура, модель данных,
> алгоритмы, сценарии, состояния, интерфейс, безопасность. Листингов production-кода нет; есть
> сигнатуры, псевдокод, таблицы и диаграммы (Mermaid). Источник истины — код в `src/**` и
> `prisma/schema.prisma`; при сомнениях верить коду.

## Краткая сводка системы

- **Продукт:** платформа турниров по паделу для одной организации-клуба (единственный администратор).
- **Стек:** Next.js 16 (App Router, TS) — RSC для чтения, Server Actions для записи; Prisma 6 + SQLite;
  Zod 4; Tailwind 4; Better Auth ^1.6. Один репозиторий, один язык.
- **Форматы:** playoff (4/8/16), round_robin, americano, mexicano. Режим подсчёта `sets`/`points`,
  free-form (без лимитов). Матчинг по 5 уровням. Только RU, тёмная тема, адаптив.
- **Данные:** 12 сущностей (4 — Better Auth, 8 — домен), аддитивная модель (round-based поверх playoff).

## Замечания «проектирование ↔ реализация» (важно для точности текста)

При выверке по коду зафиксированы два места, где спроектированная модель шире фактического поведения —
их стоит описывать аккуратно:

1. **Хранение результата playoff и `scoringMode`.** Режим подсчёта спроектирован как ортогональный
   формату, но для playoff запись результата (`recordResult`) всегда трактует ввод как сеты и пишет
   в `SetScore`; ветвления хранения playoff по `scoringMode` в коде нет. См. [06](06-podschyot-i-standings.md).
2. **`Round.status`.** Поле спроектировано с тремя состояниями (`pending/in_progress/finished`), но в
   коде не мутируется: завершённость раунда/турнира round-based форматов выводится подсчётом
   незаполненных `RoundMatch`, а не чтением `Round.status`. См. [08](08-mashiny-sostoyaniy.md).

Эти нюансы отражены в соответствующих документах честно (спроектированная модель + фактический триггер).
