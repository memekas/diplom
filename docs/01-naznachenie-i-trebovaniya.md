# 01 — Назначение системы и требования

Документ фиксирует назначение приложения «Padel Tournaments», круг пользователей, а также
функциональные и нефункциональные требования и ограничения. Это отправная точка проектирования
(глава 2): последующие документы (`03`–`11`) показывают, КАК эти требования спроектированы.

См. также: [глоссарий](02-glossariy.md), [архитектура](03-arhitektura.md),
[сценарии использования](07-stsenarii-ispolzovaniya.md).

## 1. Назначение

Веб-приложение для организации турниров по паделу. Платформа создаётся для **одной конкретной
организации (клуба)**, которая выступает администратором: только она создаёт турниры и управляет ими.
Игроки регистрируются с указанием уровня игры, участвуют одиночно или парами, просматривают информацию
о турнире и визуализацию результатов по мере их появления, а также историю прошедших турниров.

Поддерживаются **четыре формата** турниров (олимпийская / круговой / американо / мексикано) с
настраиваемым **режимом подсчёта** (сеты-геймы или просто очки). Интерфейс — только на русском языке,
тёмная тема, адаптивная вёрстка.

**Контекст.** Это **дипломная работа**, не продакшн-система: реальной нагрузки не будет. Приоритет —
простое работающее приложение, сделанное быстро, без преждевременной оптимизации и лишних фич.
Падел как предметная область важен в основном для оформления; ключевые механики — пары/одиночки,
форматы турниров и визуализация результатов.

## 2. Ключевая ценность (Core Value)

> Организация может создать турнир любого из четырёх форматов (с матчингом по уровню и выбором режима
> подсчёта), игроки регистрируются одиночно или парами, и все могут видеть визуализацию турнира с
> результатами по мере продвижения, а также историю прошедших турниров.

## 3. Акторы

```mermaid
flowchart LR
    guest([Гость]) --> player([Игрок])
    player --> admin([Администратор])
```

| Актор | Описание | Права |
|-------|----------|-------|
| **Гость** | Неаутентифицированный посетитель | Просмотр списка турниров, детальной страницы, сетки/таблицы/рейтинга; регистрация и вход |
| **Игрок** (`role = player`) | Зарегистрированный пользователь | Всё, что гость + правка своего профиля, запись на турнир (парой/одиночкой) |
| **Администратор** (`role = admin`) | Единственный аккаунт организации (seed из env) | Всё, что игрок + создание турниров, удаление регистраций, старт турнира, ввод результатов, ручное завершение |

Права наследуются по цепочке: администратор обладает всеми правами игрока, игрок — всеми правами гостя.
Подробные сценарии — в [07 — сценарии использования](07-stsenarii-ispolzovaniya.md).

## 5. Нефункциональные требования

| Категория | Требование |
|-----------|------------|
| **Простота** | Минимально сложное работающее решение; без преждевременной оптимизации и лишних абстракций (диплом) |
| **Производительность** | Реальной нагрузки нет; оптимизация под высокую нагрузку не требуется; SQLite single-writer допустим |
| **Локализация** | Только русский язык интерфейса |
| **Оформление** | Тёмная тема; адаптивная вёрстка (mobile-first, корректность примерно от 375px) |
| **Безопасность** | Серверная авторизация на границе действий и в RSC (не в middleware); типизированные ошибки — наружу только безопасные RU-сообщения; уникальность ника/email на уровне БД |
| **Среда выполнения** | Node runtime; офлайн-демонстрация без SMTP (email-верификация выключена) |
| **Целостность данных** | Транзакции для регистрации, генерации, записи результатов и переходов статуса; идемпотентная генерация сетки |
| **Сопровождаемость** | Единый язык/репозиторий; единый источник правды валидации для формы и сервера |

## 6. Ограничения (Constraints)

| Ограничение | Содержание |
|-------------|------------|
| **Технологический стек** | Next.js 16 (TypeScript, App Router) — Server Components (чтение) + Server Actions (запись); Prisma 6.x (≥6.2); SQLite; Zod 4; Tailwind 4 |
| **Библиотека аутентификации** | Better Auth `^1.6` (email+password, плагин `admin()`, Prisma-адаптер, Node runtime); email-верификация выключена для офлайн-демо |
| **Форматы** | Олимпийская — строго 4/8/16 (без bye); круговой/американо/мексикано — свободное число участников (soft-cap 24) |
| **Режимы участия** | Американо/мексикано — только одиночная регистрация (система ротирует пары); playoff/круговой — одиночные или парные |
| **Подсчёт** | Настраиваемый режим (`scoringMode`), ортогонален формату; free-form (без верхних лимитов) |
| **Администратор** | Единственный — предзаданный seed-аккаунт с ролью `admin` (идемпотентно из env); регистрация админов не предусмотрена |
| **Перечисления** | Без Prisma-enum (SQLite) — String + zod/TS-union |

## 7. Вне области (Out of Scope)

- Жеребьёвка с bye для не-степени-двойки — playoff остаётся ровно 4/8/16.
- Групповой этап и double elimination — не входят в набор форматов.
- Очки внутри гейма (15/30/40, golden point, advantage) — режим `points` считает произвольные целые на матч.
- Глобальные рейтинги игроков между турнирами — только standings внутри турнира.
- Онлайн-оплата — цена отображается, оплата в клубе.
- Real-time через websockets — обновление через `revalidatePath` после действий.
- Push/email-уведомления.
- Мобильное приложение — только адаптивный веб.
- Высоконагруженная оптимизация, кэширование, масштабирование.
