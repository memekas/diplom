## Phase Details

### Phase 6: Nicknames & Partner-by-Nick
**Goal**: У каждого игрока есть уникальный никнейм, заданный при регистрации; партнёр на турнир указывается вводом ника (точный lookup), а не выбором из списка.
**Depends on**: Phase 5 (v1.0 — register/login + участие парой уже работают; этот срез дорабатывает их).
**Requirements**: USER-01, USER-02, REG-04
**Success Criteria** (what must be TRUE):
  1. На форме регистрации есть обязательное поле «никнейм» (рядом с email/паролем/именем); без него аккаунт не создаётся, ник сохраняется в `User`.
  2. Попытка зарегистрироваться с уже занятым ником отклоняется с понятным сообщением, и аккаунт при этом не создаётся (уникальность гарантирована `@@unique` на уровне БД + проверкой при регистрации).
  3. На форме участия в турнире вместо выпадающего списка пользователей есть текстовое поле для ника партнёра; список пользователей не предлагается.
  4. Ввод существующего ника находит игрока точным lookup и регистрирует пару; ввод несуществующего ника даёт понятную ошибку и пару не создаёт.
  5. Сид-аккаунты (админ + тестовые игроки через `npm run seed:test-users`) получают валидные уникальные ники, и приложение работает «из коробки» после сидирования.
**Plans**: 1 plan
Plans:
