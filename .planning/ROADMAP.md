## Current Milestone — v3.0 UI Redesign (Court)

Визуальный рестайл всех экранов построенного фронтенда (v2.0) под зафиксированный дизайн-язык **Court**. Без новых фич, без изменений данных/схемы/backend — только визуально-вёрсточный слой. Дизайн-контракт: skill `sketch-findings-diplom` (`references/*.md`) + `.planning/sketches/` (9 экранов, тема Court). Горизонтальные слои по зависимости: дизайн-фундамент (от него зависит всё) → простые экраны аккаунта/обзора → сложные экраны визуализации турниров.

### Phases

- [x] **Phase 12: Дизайн-фундамент (Court)** — Тема Court + токены + `_base` компонентный слой в Tailwind 4 (`globals.css` / `@theme`) + container-query адаптивная база. (completed 2026-06-14)
- [ ] **Phase 13: Auth, аккаунт и обзор** — Вход/регистрация, профиль, список турниров (свёрнутые фильтры + карточки на телефоне), ЛК-дашборд по секциям — в Court.
- [ ] **Phase 14: Страницы турниров** — Страница турнира (programme), создание (форма по формату), сетка плей-офф (set-tally + games-on-hover, без счёта финала), форматные страницы (круговой / американо-мексикано) — в Court.

### Phase Details

#### Phase 12: Дизайн-фундамент (Court)

**Goal**: Дизайн-язык Court живёт в реальном Tailwind 4 — токены и компонентный слой доступны всем экранам, вёрстка реагирует на ширину контейнера через container-queries; глобальная оболочка (фон-поле, шапка, типографика) переведена на Court.
**Depends on**: Phase 11 (v2.0 — построенный фронтенд с монохромной оболочкой)
**Requirements**: UI-01, UI-10
**Success Criteria** (что должно быть ИСТИНОЙ):

  1. Загрузка приложения показывает оболочку Court (тёмное court-поле, ball-green primary, court-cyan accent, шрифты Oswald/Inter/JetBrains Mono) вместо монохромной заглушки.
  2. Все цвета/радиусы/тени берутся из токенов темы (`@theme` в `globals.css`) — захардкоженных hex в перенесённой разметке нет.
  3. Базовые компоненты (card, button, field, badge, meta-row, progress) доступны как переиспользуемый `_base` слой и применяются на уже отрисованных поверхностях (главная, шапка).
  4. Контейнер приложения адаптируется через container-queries (`container-type: inline-size` + `@container`), а не media-queries — раскладка корректна при сужении контейнера до ~375px без непреднамеренного горизонтального скролла.

**Plans**: 2 plans

- [x] 12-01-PLAN.md — Court token contract + _base component layer + next/font (Oswald/Inter/JetBrains Mono) + Court body shell + container-query convention (globals.css, layout.tsx)
- [x] 12-02-PLAN.md — Restyle global chrome (Nav, tournament-status-badge) onto Court tokens/classes + verify ≤375px shell, no unintended horizontal scroll (nav.tsx, tournament-status-badge.tsx)

**UI hint**: yes

#### Phase 13: Auth, аккаунт и обзор

**Goal**: Экраны входа/регистрации, профиля, списка турниров и ЛК-дашборда оформлены в Court — читаемы на десктопе и на телефоне (~375px), используют компонентный слой Phase 12.
**Depends on**: Phase 12 (тема + компонентный слой)
**Requirements**: UI-02, UI-03, UI-04, UI-05
**Success Criteria** (что должно быть ИСТИНОЙ):

  1. Auth-экран — таб-карточка Court с вкладками Вход/Регистрация; поля и состояния (ошибки/disabled) читаемы на десктопе и на ~375px.
  2. Профиль показывает карточку игрока (имя, @ник, уровень, сторона) и форму редактирования реальных полей (Имя, Никнейм, Сторона, Телефон, Уровень, Дата рождения) с Email как read-only логином — в стиле Court.
  3. Список турниров — плотный список на десктопе и карточка-на-строку на телефоне; кнопка «Фильтры» открывает поповер (Статус/Формат/Уровень/Вид) + поиск, на кнопке виден бейдж числа активных фильтров.
  4. ЛК-дашборд показывает «Мои турниры» секциями Активные / Предстоящие / Завершённые с ролью игрока (пара с… / одиночный) и CTA — в Court.

**Plans**: 4 plans (Wave 1 — все параллельны, файловые наборы непересекающиеся)

#### Phase 14: Страницы турниров

**Goal**: Страница турнира, форма создания и все виды визуализации результатов (плей-офф сетка + форматные страницы) переведены на Court с сохранением v2.0-функциональности; сложные раскладки (сетка/широкие таблицы) корректны на 4/8/16 и на телефоне.
**Depends on**: Phase 12 (тема + компонентный слой); параллельна Phase 13
**Requirements**: UI-06, UI-07, UI-08, UI-09
**Success Criteria** (что должно быть ИСТИНОЙ):

  1. Страница турнира — programme-вёрстка Court: hero (название + статус), регламент-мета, стартовый лист с посевом и подсветкой «ваша пара», прогресс набора, CTA участия.
  2. Форма создания турнира (админ) в Court меняет поля по формату: Олимпийская → выбор сетки 4/8/16; Круговой → число участников; Американо/Мексикано → Тип=Одиночный и Подсчёт=Очки заблокированы и появляется «Число раундов».
  3. Сетка плей-офф в Court рендерит колонки раундов с карточками матчей (полные имена + set-tally), показывает счёт по геймам по наведению/тапу, скрывает счёт финала, отображает баннер чемпиона; карточки и соединительные линии выровнены на 4/8/16 (намеренный горизонтальный скролл допустим).
  4. Форматные страницы в Court: Круговой показывает «Матчи» по раундам + «Турнирную таблицу»; Американо/Мексикано — «Текущие/Прошедшие игры» + «Рейтинг игроков».
