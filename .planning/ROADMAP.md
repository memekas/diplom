## Current Milestone

### v2.0 — Мультиформатные турниры + полный UX

**Goal:** Расширить движок с единственного playoff-для-пар до четырёх форматов (playoff / round-robin / американо / мексикано) с одиночной и парной записью, матчингом по уровню и настраиваемым режимом подсчёта (сеты-геймы или просто очки, без лимитов), и довести UX до бизнес-требований (только русский, тёмная тема, адаптив, главная со списком открытых турниров, шапка с ЛК, расширенный личный кабинет).

**Granularity:** coarse (5 фаз, few-large-phases)
**Phase structure:** строгие горизонтальные слои — Слой 1 (модель данных) → Слой 2 (бэкенд) → Слой 3 (фронтенд/UX). Все фазы слоя завершаются до начала следующего слоя.
**Coverage:** 24/24 требований замаплены ✓

#### Locked Decisions (контекст для всех фаз — не пересматривать)

1. **Американо/мексикано** = одиночная регистрация + системная ротация пар по раундам; индивидуальные очки; итог = рейтинг игроков. Парная-по-нику только для playoff и round-robin.
2. **Матчинг уровня** = строгое равенство (5 RU-уровней: новичок / прогрессирующий / средний / высокий / профессиональный).
3. **Размеры**: playoff = ровно 4/8/16 (без bye); round-robin/американо/мексикано = свободное число участников.
4. **ЛК** правит всё, включая email (флоу смены email Better Auth) и ник (с проверкой уникальности).
5. **scoringMode** (`sets` | `points`) — настройка турнира, ортогональна формату; без верхнего лимита на сеты/геймы/очки.
6. **Завершение турнира** — ручное действие админа (для всех форматов); авто-финиш playoff дополняется кнопкой.

#### Existing system (расширять, не переписывать)

Stack: Next.js 16 App Router + Prisma 6 + SQLite + Zod + Tailwind 4 + Better Auth ^1.6. Без Prisma-enums (String + zod-union). Пароль в `Account.password` (scrypt). PLAYOFF полностью реализован (single-elim Match-дерево, `nextMatchId`-проводка, теннисный счёт сеты/геймы, продвижение, авто-финиш). Текущие модели: User, Tournament(name/size/status/date/location/setsPerMatch/gamesPerSet), Pair, Match, SetScore. v2.0 РАСШИРЯЕТ их, не ломая playoff.

## Phase Details

### Phase 7: Модель данных мультиформата
**Goal**: Prisma-схема, миграция и сиды описывают все четыре формата, одиночных и парных участников, обязательный уровень/дату рождения и настраиваемый режим подсчёта — фундамент данных, на котором строится весь бэкенд v2.0, без поломки существующих playoff-данных.
**Depends on**: Phase 6 (shipped — текущая схема User/Tournament/Pair/Match/SetScore)
**Requirements**: DATA-01, DATA-02, DATA-03, DATA-04, DATA-05, DATA-06, DATA-07
**Success Criteria** (what must be TRUE):
  1. Миграция применяется чисто (допустимы `migrate reset` + reseed) и `prisma generate` проходит без ошибок; существующая playoff-структура (Match-дерево, SetScore) сохраняется.
  2. `User` имеет обязательный `skillLevel` (одно из 5 RU-значений, валидируется zod-union) и опциональный `birthDate`; сиды (`seed.ts`, `seed-test-users.ts`) создают пользователей с валидным уровнем и без нарушения `@@unique` ника.
  3. `Tournament` хранит `format` (playoff/round_robin/americano/mexicano), `kind` (singles/pairs), `level` (5 RU), `price`, и `scoringMode` (sets/points) с настраиваемыми `setsPerMatch`/`gamesPerSet` без верхнего лимита.
  4. Схема поддерживает участника как одиночного игрока ИЛИ пару, расписание round-robin (каждый-с-каждым) и раунды американо/мексикано с индивидуальными очками игрока; «очковый» результат хранится как произвольные целые на сторону.
  5. Prisma Studio показывает заполненные сидами таблицы со всеми новыми полями и связями; запросы по новым моделям возвращают данные.

### Phase 8: Ядро бэкенда (создание, регистрация, админ, ЛК)
**Goal**: Server Actions и сервисы позволяют админу создать турнир любого формата с форматно-зависимой валидацией размера, игрокам — записаться одиночно или парой только своего уровня, админу — удалять регистрации и вручную завершать турнир, а игроку — править все поля профиля включая email и ник.
**Depends on**: Phase 7
**Requirements**: TOUR-05, REG-05, REG-06, ADMN-01, ADMN-02, USR-03
**Success Criteria** (what must be TRUE):
  1. Создание турнира принимает формат/вид/уровень/количество/цену; валидация размера ветвится по формату (playoff — только 4/8/16; round-robin/американо/мексикано — свободное число) и отклоняет невалидные комбинации.
  2. Регистрация отклоняется при несовпадении уровня игрока и уровня турнира (строгое равенство); одиночная запись работает для singles и обязательна для американо/мексикано, парная (по нику) — для pairs-форматов.
  3. Админ может удалить зарегистрированного участника/пару на этапе открытой регистрации, и может вручную завершить турнир любого формата (action отрабатывает + `revalidatePath`).
  4. Действие ЛК сохраняет правки ФИО/уровня/телефона/даты рождения/ника (с проверкой уникальности) и email (через флоу смены email Better Auth); конфликт ника даёт понятную RU-ошибку, не падение.
  5. Все новые actions проходят серверные гварды роли (создание/удаление/завершение — только admin) и zod-валидацию входа.

### Phase 9: Движки форматов и подсчёта
**Goal**: При старте/продвижении каждый формат генерирует и обновляет свою структуру (round-robin-расписание, ротация и индивидуальные очки американо/мексикано, существующее playoff-дерево), а ввод результата ветвится по режиму подсчёта (`sets` без лимитов либо `points` — два произвольных целых) с корректным вычислением победителя.
**Depends on**: Phase 8
**Requirements**: FMT-01, FMT-02, FMT-03, SCORE-01
**Success Criteria** (what must be TRUE):
  1. Старт round-robin генерирует полное расписание «каждый-с-каждым»; после ввода всех результатов формируется корректная турнирная таблица (standings).
  2. Старт/продвижение американо/мексикано формирует и ротирует составы по раундам и накапливает индивидуальные очки игроков; итог — рейтинг игроков.
  3. Ввод результата в режиме `sets` принимает произвольное число сетов и геймов без лимита (правило победы сета обобщено под настраиваемый `gamesPerSet`); в режиме `points` — два произвольных целых, победитель у кого больше; победитель матча вычисляется по режиму.
  4. После ввода результата формируется следующий раунд / обновляются standings для каждого формата; playoff-продвижение и авто-финиш продолжают работать без регрессии.

### Phase 10: UX-фундамент (локализация, тема, адаптив, главная, шапка)
**Goal**: Весь сайт на русском, в принудительной тёмной теме и адаптивен; пользователь попадает на главную со списком открытых для регистрации турниров и видит шапку с названием клуба, логотипом, кнопкой «Прошедшие турниры» и входом в личный кабинет.
**Depends on**: Phase 9
**Requirements**: SITE-01, SITE-02, SITE-03, HOME-01, HDR-01
**Success Criteria** (what must be TRUE):
  1. Все экраны (вход/регистрация, dashboard, профиль, навигация) на русском с `<html lang="ru">`, включая подписи 5 RU-значений уровня.
  2. Весь сайт отображается в тёмной теме без захардкоженных светлых элементов (значки статуса/алерты исправлены).
  3. Интерфейс корректно адаптируется под desktop и мобильные устройства (без горизонтального скролла/обрезки ключевых блоков).
  4. Главная страница показывает список открытых для регистрации турниров; с неё можно перейти на турнир.
  5. Шапка содержит название клуба, логотип, кнопку «Прошедшие турниры» и вход в личный кабинет на всех страницах.

### Phase 11: UX турниров (формы, ввод счёта, визуализация)
**Goal**: Полный пользовательский путь по турнирам: админ создаёт турнир со всеми полями и режимом подсчёта, игрок регистрируется (одиночно/парой по виду турнира) с уровнем и датой рождения, админ вводит результаты по режиму и управляет турниром, а все видят визуализацию активного турнира по его формату и историю прошедших.
**Depends on**: Phase 10
**Requirements**: FORM-01, FORM-02, FORM-03, SCORE-02, VIS-01, VIS-02
**Success Criteria** (what must be TRUE):
  1. Форма создания турнира предоставляет поля формат/одиночный-парный/уровень/количество/цена, селектор режима подсчёта и (для `sets`) поля числа сетов/геймов без верхнего предела.
  2. Форма регистрации собирает обязательный уровень (5 RU) и дату рождения; UI поддерживает одиночную и парную (ник партнёра) запись по виду турнира.
  3. Расширенная форма ЛК правит все поля профиля; админ-элементы позволяют удалить зарегистрированную пару/участника и вручную завершить турнир.
  4. Ввод результата админом ветвится по режиму (N сет-строк против двух полей очков); счёт визуализируется согласно режиму.
  5. Визуализация активного турнира зависит от формата (playoff-сетка, таблица round-robin, standings/раунды американо-мексикано) с панелями «текущие»/«прошедшие игры»; завершённые турниры доступны для просмотра с историей матчей по формату.
