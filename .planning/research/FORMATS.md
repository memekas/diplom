## 0. Сводка: чем форматы отличаются (водораздел)

| | Единица | Партнёр | Расписание | Очки | Итог | Старт |
|---|---|---|---|---|---|---|
| **Playoff** (есть) | пара | фиксирован | дерево на вылет | сеты/геймы | пара-чемпион | всё дерево сразу |
| **Round-robin** | пара ИЛИ игрок | фиксирован | каждый-с-каждым, **весь график заранее** | за матч (1/0) | топ таблицы | все матчи сразу |
| **Американо** | игрок (одиночка) | **ротирует по фикс. схеме** (circle) | заранее, не зависит от результатов | индивид. (сумма на матч) | рейтинг игроков | всё расписание сразу |
| **Мексикано** | игрок (одиночка) | **ротирует по рейтингу** | **раунд за раундом**, зависит от таблицы | индивид. (сумма на матч) | рейтинг игроков | только раунд 1; дальше по результатам |

**Главное архитектурное следствие:** playoff и round-robin строятся «всё сразу» (stateless-генерация); **мексикано** материализует раунды по одному (нужно ждать результатов предыдущего). Американо/мексикано используют **индивидуальные** очки и **4 игрока на матч** (2 динамические команды), а не фиксированную `Pair`.

## 1. Round-robin (круговой)

**Что:** каждая единица играет с каждой другой ровно раз (single) или дважды (double). Итог — по накопленной таблице, без дерева. Соревновательный (в отличие от социальных американо/мексикано). Единица = **пара** (парный RR, регистрация по нику как в playoff) ИЛИ **игрок** (одиночный 1v1). Партнёр НЕ ротирует.

### Алгоритм расписания (circle / polygon method) — детерминированный, готов к коду
```
ВХОД: units[] (pairId для парного | userId для одиночного), длина n0
ШАГ 0: shuffle(units) ОДИН раз (Fisher–Yates, как shuffle() в bracket.ts — Math.random только тут)
        if (n0 нечётное) units.push(BYE)   // BYE = сентинел (null)
        n = units.length (чётное); rounds = n-1; half = n/2
ШАГ 1: arr = units.slice(); arr[0] фиксирован НАВСЕГДА; ротирует только хвост [1..n-1]
ШАГ 2: for r = 0..rounds-1:
          for i = 0..half-1:
            home = arr[i]; away = arr[n-1-i]
            if (home==BYE || away==BYE) -> та сторона ОТДЫХАЕТ, матч НЕ создаётся
            else -> Match(round=r+1, position=i, unitA=home, unitB=away)
          // ротация: const fixed=arr[0]; const tail=arr.slice(1); tail.unshift(tail.pop()); arr=[fixed,...tail]
ИНВАРИАНТ: каждая единица встретит каждую ровно 1 раз. Матчей всего = n0*(n0-1)/2.
double RR -> повторить цикл второй раз (опц. swap home/away).
```
**⚠️ Частые ошибки (из верификации):** (1) ротировать ВСЕ элементы включая `arr[0]` → дубли/пропуски. Фикс: `arr[0]` всегда на месте. (2) забыть BYE для нечётного N → неверное число раундов. (3) создавать bye как реальный матч → мусор в таблице — НЕ создавать.

### Подсчёт и таблица
- Очки **за матч**: победа = +1 (в падел ничьих нет в `sets`-режиме → 1/0). Победитель матча: `sets` → большинство сетов (переиспользуем `matchWinnerFromSets`); `points` → больше очков.
- **⚠️ В `points`-режиме возможна НИЧЬЯ** (напр. 21:21) — `setWinner` физически не может вернуть ничью, но два произвольных целых могут быть равны. **Решение нужно:** либо запретить равные очки в zod, либо схема 2/1/0 (победа/ничья/поражение). → см. «Решения».
- Таблица: для каждой единицы `played/wins/losses/points` + вторичные агрегаты.

### Тай-брейкеры (зафиксировать ДО турнира; источники расходятся по месту H2H)
- `sets`: 1) победы в матчах → 2) set diff → 3) sets won → 4) game diff → 5) games won → 6) личная встреча → 7) стабильный фолбэк по id.
- `points`: 1) победы → 2) point diff (for−against) → 3) total points → 4) личная встреча → 5) id.
- «Circle of death» (A>B>C>A) — норма, разрешается следующим тай-брейкером.

### Размер
Свободное N (НЕ степень двойки). Чётное → N−1 раундов, byes нет. Нечётное → +1 BYE, N раундов, каждый сидит ровно 1 раз. Рекомендую cap (≤16–20 единиц): матчей = N(N−1)/2 растёт квадратично (16 = 120 матчей). Мин 2 (вырожденно), практ. 3–4.

### scoringMode
Работает в обоих. `sets` — самый «теннисный», богатые тай-брейкеры (set/game diff), идеален для парного competitive RR. `points` — проще, нужны поля `pointsA/pointsB` на матче.

## 2. Американо

**Что:** социально-соревновательный. Регистрация **одиночная**; партнёр **меняется каждый раунд** (цель — каждый сыграл в паре с каждым). Очки **индивидуальные**. Итог — **рейтинг игроков** (не пара-чемпион). Всё расписание генерится при старте (не зависит от результатов).

### Алгоритм (circle method на ИГРОКАХ — гарантирует «партнёр-once»)
```
1. Индексируем игроков 0..N-1 (N чётное; нечётное/не-кратное-4 → см. размер). Pad BYE если нужно.
2. arr[0] фиксирован, остальные в кольце.
3. for r = 0..N-2:
     arr = [0] + ring
     ПАРТНЁРСТВА: пары позиций (i, N-1-i): (arr[0],arr[N-1]),(arr[1],arr[N-2]),... → N/2 партнёрств
       (за N-1 раундов каждый игрок партнёрит каждого ровно раз; проверено N=4/8/12/16 → 0 дублей)
     КОРТЫ: корт k = партнёрство(2k) vs партнёрство(2k+1) → N/4 кортов
       (назначение СОПЕРНИКОВ — вторично; «партнёр-once» — определяющая гарантия)
     ротация кольца на 1: ring = [ring[-1], ...ring[:-1]]
Пример 4 игрока: R1 (0&3 vs 1&2), R2 (0&2 vs 3&1), R3 (0&1 vs 2&3).
```
**⚠️ Из верификации:** «партнёр-once» — гарантия circle-метода; **уникальность СОПЕРНИКОВ НЕ гарантируется** одновременно (для N не кратных 4 и при больших N полный микс недостижим — это нормально, не баг). Не пытаться гарантировать оба.

### Подсчёт (КАНОН — points-to-target)
- Матч играется до **фиксированной суммы очков** (16 / **24** UK-дефолт / 32 для равной подачи). Каждый розыгрыш = 1 очко команде. Матч кончается когда суммы сторон = target (24 → 15:9, 16:8, **12:12 ничья допустима**).
- **Оба игрока команды получают в личный зачёт счёт СВОЕЙ команды** (15:9 → оба победителя +15, оба проигравших +9). **⚠️ Частая ошибка:** начислять очки победителя проигравшим или «делить» очки — НЕТ, каждый партнёр получает ОДНО командное число.
- `scoringMode='points'` ложится точно: два целых, сумма = `targetPoints`.

### Итог / тай-брейкеры
Сумма личных очков по всем раундам, desc. Сидевшие раунды НЕ штрафуются (просто меньше вкладов). Тай-брейк — **опция организатора** (не канон формата): дефолт проекта `сумма → личная встреча → point diff → id`.

### Размер
Мин **4** (1 корт). Идеал — кратно 4 (никто не сидит). N чётное-не-кратно-4 (6,10) → лишнее партнёрство (2 игрока) сидит. Нечётное N → +1 BYE, 1 игрок сидит. **Число сидящих:** N≡0 mod4 → 0; нечётное → 1; N≡2 mod4 → 2. Cap сверху мягкий.

### scoringMode
`points` — **идиоматичный и единственный задокументированный** режим. `sets` для американо — **проектное расширение без внешнего прецедента** (вклад игрока = выигранные геймы). На защите честно сказать: points — канон.

## 3. Мексикано

**Что:** как американо (одиночки, индивидуальные очки, итог-рейтинг), НО пары/соперники следующего раунда формируются **динамически по текущей таблице**. Самобалансирующийся: матчи становятся ровнее к концу. Повтор партнёров/соперников допустим (уникальность НЕ цель).

### Алгоритм (по раундам)
```
РАУНД 1 (baseline): shuffle игроков; нарезать по порядку на четвёрки [p0,p1,p2,p3];
   команда A=(p0,p1), B=(p2,p3); корт = индекс четвёрки. (опц. сид по skillLevel — не канон)
РАУНДЫ 2..R (рейтинг-зависимые):
   1. Пересчитать кумулятивную таблицу (сумма личных очков за сыгранные раунды)
   2. Отсортировать всех по убыванию очков → ranks[0..N-1] (тай-брейк сортировки детерминирован!)
   3. Нарезать на ПОСЛЕДОВАТЕЛЬНЫЕ четвёрки: группа g = ranks[4g..4g+3]
      (группа 0 = места 1-4 на Корт 1, группа 1 = места 5-8 на Корт 2, ... → «сильные vs сильные»)
   4. Внутри четвёрки (локальные места s0<s1<s2<s3) — кросс-разведение, ДВА паттерна (выбрать ОДИН):
      • «1+4 vs 2+3»: A=(s0,s3), B=(s1,s2)  → суммы 5=5, РОВНЫЕ команды
      • «1+3 vs 2+4»: A=(s0,s2), B=(s1,s3)  → лидер с 3-м против 2-го+4-го
   5. Назначить группу на корт (g+1). Повторить.
```
**⚠️ КЛЮЧЕВАЯ ПОПРАВКА верификации (паттерн четвёрки):** оба паттерна широко задокументированы, счёт источников ~**4:3 в пользу «1+4 vs 2+3»** (americano-padel.app, padelpuffin, padeli, bandejapadel) против «1+3 vs 2+4» (liveforpadel, padelmix, pistas365). Утверждение «1+4vs2+3 каноничнее/балансированнее» — НЕ подтверждено источниками как канон (это интерпретация); часть источников выбирает «1+3vs2+4» именно как стандарт «сильные против сильных». **→ решение организации, зафиксировать явно.** См. «Решения».

**⚠️ Не путать с King-of-the-Court / «Super Mexicano»** (победитель матча → корт выше): это ОТДЕЛЬНЫЙ формат, НЕ берём. Classic Mexicano пересортировывает ВСЮ таблицу и заново режет на четвёрки.

### Подсчёт — идентичен американо (points-to-target, индивидуальный). target настраиваемый (12/16/21/24/32 — НЕ зашивать фикс-набор, любое положительное целое).

### Итог / тай-брейкеры
Сумма личных очков desc; **эта же таблица — вход для пар следующего раунда** (пересчёт после КАЖДОГО раунда). Для детерминизма группировки **тай-брейк при равенстве очков обязателен** (иначе нарезка на четвёрки недетерминирована). Дефолт: `сумма → point diff (нужен pointsAgainst) → число побед → id`.

### Размер
Мин **8** (нужно ≥2 кортов — на 1 корте рейтинг-нарезка бессмысленна). Идеал кратно 4. Не-кратно-4 → 1–3 сидят, **распределять byes равномерно** (счётчик пропусков на игрока; в bye — с наименьшим числом пропусков). Свободное N≥8 (не степень двойки).

### scoringMode
`points` — родной. `sets` — ломает однозначность вклада в рейтинг → для мексикано фактически только `points` (или явно определить вклад=геймы, нестандартно).

## 4. Выводы для МОДЕЛИ ДАННЫХ (Фаза 7) — что схема ОБЯЗАНА вместить

**⚠️ Главный риск (из обеих линз верификации):** текущий `Match` жёстко завязан на single-elim — `pairAId/pairBId/winnerId` = FK на `Pair` (named relations `MatchPairA/B/Winner`), плюс `nextMatchId/nextSlot/position/@@unique([tournamentId,round,position])`. **Нельзя** просто навесить 4 FK на User + nullable-поля — это даёт два взаимоисключающих набора полей, конфликт `@@unique`, и ломает `recordResult` (он требует `pairAId&&pairBId`, иначе `slots_unfilled`; `winnerId` — FK на Pair, не может указать на игрока).

**Рекомендация (диплом — изоляция риска, НЕ ломать playoff):** оставить стек playoff (`Match/Pair/SetScore`) как есть; для round-based/индивидуальных форматов завести отдельные модели:

1. **`Tournament`** (+поля): `format` (`playoff|round_robin|americano|mexicano`), `scoringMode` (`sets|points`), `participantMode` (`pairs|singles`), `targetPoints Int?` (для points-режима американо/мексикано), `totalRounds Int?` (американо/мексикано), `setsPerMatch`/`gamesPerSet` → **nullable / без верхнего лимита** (сейчас `@default(3)/(6)`; снять зашитость), `size` → **сделать семантически-зависимым от format** (не обязательно {4,8,16}).
2. **`TournamentPlayer`** (новая, для одиночной заявки): `tournamentId, userId, @@unique([tournamentId,userId])`. `Pair` остаётся для парных форматов.
3. **`Round`** (новая, для round-based): `tournamentId, roundNumber, status`. Нужна т.к. мексикано материализует раунды по одному.
4. **`RoundMatch`** (новая, для RR/американо/мексикано) ИЛИ обобщённый матч: `roundId, courtNumber`, команды как **4 FK на User** (`teamA1/teamA2/teamB1/teamB2`, для одиночного RR — 1v1, два FK), результат. Не трогает playoff-`Match`.
5. **`PlayerMatchScore`** (новая): `roundMatchId, userId, teamSlot, pointsFor, pointsAgainst`. **Оба партнёра получают ОДНО командное `pointsFor`.** `pointsAgainst` НЕ опционален (нужен для тай-брейка #2 и детерминизма мексикано-нарезки).
6. **Очковый результат**: для `points`-режима хранить два целых на матч (`pointsA/pointsB`), НЕ прогонять через `setWinner`/`SetScore` (счёт 15:9 провалит `isValidSet`). Валидация `points` = два неотрицательных целых (+опц. сумма == `targetPoints`).
7. **`migrate reset` + reseed** допустимы (диплом). Сиды добавляют обязательный `skillLevel` (5 RU) + `birthDate`.

Альтернатива (если хочется меньше таблиц): обобщить `Match` через дискриминатор `format` + nullable-поля — дешевле по таблицам, но хрупко (нужно nullable `position`/`pairA/B`, ослабить `@@unique`, ветвить `recordResult`). Решение — на discuss/plan фазы 7.

## 5. Выводы для БЭКЕНДА (Фаза 9) — что движки ОБЯЗАНЫ учесть

- **Старт турнира format-зависимый:** `generateBracket` (требует size∈{4,8,16}, size-1 матчей, seed, всё дерево) — только playoff. Для RR — circle-method всё расписание сразу. Для американо — circle-method всё расписание сразу. Для мексикано — только Раунд 1 (shuffle+нарезка), дальше по результатам.
- **`recordResult` нельзя переиспользовать как есть:** шаг 9 (`nextMatchId==null` → финиш турнира) сработает для RR/американо после ПЕРВОГО матча (у них у всех `nextMatchId=null`). Нужна ветка по `format`: round-based — пропустить advancement (шаг 8) и авто-финиш (шаг 9); финиш — отдельным условием (все матчи всех раундов сыграны) либо ручной кнопкой админа.
- **Мексикано — gating:** следующий Round материализуется только когда ВСЕ матчи текущего раунда имеют результат; пересортировка таблицы с детерминированным тай-брейком.
- **Статус-машина** (`registration→in_progress→finished`) переиспользуется как есть; меняется лишь УСЛОВИЕ перехода в `finished` для round-based.
- **Валидация size** (`tournamentSizes=[4,8,16]`) — ветвить по format: playoff → {4,8,16}; RR → N≥2..cap; американо → N≥4; мексикано → N≥8.
