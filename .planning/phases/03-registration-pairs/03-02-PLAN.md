## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form → participateAction | player2Id untrusted; player1 MUST be the session user, never the form |
| participateAction → registerPair (Plan 01) | re-checks status/capacity/duplicates atomically in one transaction |
| RSC page → client | only safe player fields (name/courtSide/skillLevel) cross to the client; never email/credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Spoofing/Elevation | participateAction caller identity | mitigate | first line `requireUser()`; player1Id = session `user.id` (Pitfall 8); anonymous direct POST rejected before any DB work |
| T-03-05 | Tampering | client-supplied player1 / role | mitigate | action never reads player1Id/role from the form — derived solely from the session |
| T-03-06 | Information Disclosure | participant list / partner select leaking PII | mitigate | listTournamentPairs + listEligiblePartners use explicit safe `select` (name, courtSide, skillLevel, id) — no email/credential columns (Pitfall 12) |
| T-03-07 | Repudiation/Integrity | stale list after registration | mitigate | `revalidatePath('/tournaments/${id}')` in the action after commit; verified on prod build (Pitfall 10) |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | no package installs in this phase (no new deps — CONSTRAINTS) |
</threat_model>
