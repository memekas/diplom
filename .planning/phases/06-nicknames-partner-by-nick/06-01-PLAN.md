<notes>
## Test runner reality (READ — do not assume vitest/npm test)
This project has NO aggregate test runner and NO vitest. Every `*.test.ts` is a self-contained `tsx` assertion script that exits non-zero on failure. Run a test with `npx tsx <file>`. The only npm scripts are `dev`, `build`, `start`, `lint`, `seed:test-users`. The typecheck/compile gate is `npm run build`.

## Migration path (locked — Finding 2 / CONTEXT)
`dev.db` is gitignored, no real data, thesis. Adding a required UNIQUE column uses `npx prisma migrate reset --force` (drops + recreates empty, applies the new migration with zero rows so `NOT NULL`+`UNIQUE` apply cleanly), then reseed. Do NOT attempt `migrate dev` against a populated table — it aborts on "required column without default". `migrate reset` auto-runs the `prisma db seed` hook (admin); test users are reseeded separately via `npm run seed:test-users`.

## Duplicate-nickname error shape (locked — Finding 1 / Pitfall 1+2)
A `nickname` unique collision at `signUp.email` surfaces as `error.code === "FAILED_TO_CREATE_USER"` (English message "Failed to create user", HTTP 422) — NOT a nickname-specific code, NOT `error.message`. signUp is atomic for this path: no orphan User/Account row. The duplicate-EMAIL case returns a different, earlier code `"USER_ALREADY_EXISTS_USE_ANOTHER_EMAIL"`. The form MUST branch on `error.code`. Assumption A1: in this schema `nickname` is the only create-time unique column besides the pre-checked email, so `FAILED_TO_CREATE_USER` ⇒ nickname collision.

## Case sensitivity (locked — Finding 2)
SQLite TEXT UNIQUE is BINARY/case-sensitive by default. This matches the locked exact-match decision for both the `@@unique` and the REG-04 `where: { nickname }` lookup. Do NOT add `COLLATE NOCASE`.
</notes>
