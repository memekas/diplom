<objective>
Deliver the profile vertical slice: a signed-in user views their own profile and edits the display-only domain fields — courtSide (left/right/either), phone, and skillLevel. Edits go through a `requireUser`-guarded Server Action → Zod validation → service-layer update → `revalidatePath`, following the established thin-action / fat-service pattern.

Implements PLAYER-03 (player edits own profile: court side, phone, skill level). These fields are display-only in v1 (no domain logic) — courtSide here is where the "either" default (set at signup in plan 01) becomes user-editable.

Purpose: Completes the auth/profile foundation; establishes the read-via-service + mutate-via-guarded-Server-Action convention that phases 2–5 reuse.
Output: Profile service, validation schema, profile view page, edit form, and the guarded update action.
</objective>
