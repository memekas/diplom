  <behavior>
    Read `bracket.ts` for the exact house style first: framework-agnostic exports, a typed `*Error extends Error` class with a `code` discriminant + RU message, JSDoc-style comment blocks. Read `bracket.test.ts` for the exact harness: `import assert from "node:assert/strict"`, a `check(name, fn)` counter, synchronous cases top-level, `console.log` per pass, exits non-zero on failure (no test framework).

    Define a typed error (NOT plain Error) so Plan 02/03 can map rejects without string-matching:
    `ResultError extends Error` with `code: "invalid_set" | "slots_unfilled" | "no_winner" | "empty"` (slots_unfilled / no_winner / empty are consumed by Plan 02's recordResult; invalid_set is thrown here) and an RU `message`. Set `this.name = "ResultError"`.

    `setWinner(gamesA: number, gamesB: number, gamesPerSet: number): "A" | "B"`
    A set is VALID and won when EITHER:
      (a) the higher score === gamesPerSet AND the margin (higher − lower) >= 2  — e.g. for gamesPerSet 6: 6:0, 6:1, 6:2, 6:3, 6:4 (and the mirror 0:6 … 4:6); OR
      (b) it is a tiebreak: the winner has exactly gamesPerSet+1 and the loser has exactly gamesPerSet — e.g. 7:6 / 6:7 for gamesPerSet 6.
    Returns "A" if gamesA is the winning side, "B" if gamesB is. Throw `ResultError("invalid_set", <RU msg including the two scores>)` for everything else: 6:5 (winner reached gamesPerSet but margin 1, not a tiebreak), 4:4 (neither reached gamesPerSet), 8:6 (winner overshot gamesPerSet+1), 6:6 (tie), 7:7, any negative game count, non-integers, and any input where neither side has a clear win under (a) or (b). Equal scores never produce a winner.

    `matchWinnerFromSets(setWins: ("A" | "B")[], setsPerMatch: number): "A" | "B" | null`
    needed = Math.ceil(setsPerMatch / 2)  (= 2 when setsPerMatch is 3). Count "A" wins and "B" wins in `setWins`. Return the first side to reach `needed`; if neither has reached `needed`, return null (undecided — do NOT throw here, recordResult decides whether null is a reject). Extra trailing sets beyond a decided match are tolerated by counting (a 2:1 where the array is ["A","B","A"] still returns "A"); a still-running array like ["A","B"] for setsPerMatch 3 returns null.

    Cases the test MUST cover (gamesPerSet = 6, setsPerMatch = 3 unless noted):
    - setWinner valid: 6:4 → "A", 4:6 → "B", 7:5 → "A", 6:0 → "A", 0:6 → "B", 6:3 → "A", 7:6 → "A", 6:7 → "B".
    - setWinner invalid (each throws ResultError code "invalid_set"): 6:5, 5:6, 4:4, 8:6, 6:6, 7:7, 6:8, -1:6, 6:-1, 3:3, 0:0.
    - setWinner with a different gamesPerSet (e.g. gamesPerSet 4): 4:2 → "A", 5:4 → "A" (tiebreak), 4:3 → invalid, 4:4 → invalid (proves the rule reads the param, not a hardcoded 6).
    - matchWinnerFromSets: ["A","A"] → "A" (2:0); ["A","B","A"] → "A" (2:1); ["B","A","B"] → "B"; ["A","B"] → null (undecided, 1:1 with a set left); [] → null; ["A"] → null; (setsPerMatch 1) ["A"] → "A" (needed = 1).
  </behavior>
