<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → startTournamentAction | A Server Action is a public HTTP endpoint. tournamentId is bound from the page; role/identity come from the signed session cookie, never the form. |
| anonymous → detail page (read) | Bracket viewing is intentionally public; the read path exposes only pair display names (no PII/credentials). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Elevation of Privilege | non-admin POSTing startTournamentAction | mitigate | requireAdmin() is the action's FIRST line; throws "Forbidden" before generateBracket runs. Hiding the button for non-admins is cosmetic only (Pitfall 8 / AUTH-05). |
| T-04-05 | Tampering | re-clicking «Старт» / racing two starts to re-generate (BRKT-03) | mitigate | The action delegates to generateBracket whose $transaction guard rejects when status != registration or any Match exists (Plan 01). The disabled button is cosmetic; the data-layer guard is authoritative. |
| T-04-06 | Information Disclosure | bracket read path leaking user PII | accept | The match query selects only player display names (no email/phone/credential columns), consistent with listTournamentPairs' safe select. Public viewing is a requirement (BRKT-02). |
| T-04-07 | Tampering | stale public bracket after start (Pitfall 10) | mitigate | revalidatePath(`/tournaments/${id}`) inside the action purges data + Router cache so the bracket renders immediately. Verified against `npm run build` (prod-like), not just dev. |

No npm/pip/cargo installs in this plan (no new deps — constraint; bracket is plain Tailwind, no bracket library) → no package-legitimacy checkpoint needed.
</threat_model>
