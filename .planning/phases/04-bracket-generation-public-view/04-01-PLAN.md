| Boundary | Description |

| caller → generateBracket | Service is invoked from a Server Action (Plan 02). It must NOT trust that the caller pre-checked status/capacity/existing-matches — it re-reads and re-guards everything from the DB inside the transaction. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | generateBracket re-shuffle / re-generate after start (BRKT-03) | mitigate | Inside the $transaction: reject if status != "registration" OR if tx.match.count > 0. Generate-once is enforced at the data layer, not just the UI (Pitfall 3). |
| T-04-02 | Tampering | partial bracket persisted on mid-generation failure | mitigate | Entire read→shuffle→create→wire→transition runs in one prisma.$transaction; any throw rolls back — no orphan matches, no seeds-without-matches (Pitfall 1/2). |
| T-04-03 | Elevation of Privilege | non-admin triggering generation | transfer | Authorization is the Server Action's first line (requireAdmin) in Plan 02 (T-04-04 there). The service is framework-agnostic and intentionally guard-free for role — same split as registerPair/participateAction. |
