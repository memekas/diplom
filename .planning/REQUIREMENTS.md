# Requirements: Padel Tournaments

**Defined:** 2026-06-06
**Core Value:** Организация создаёт playoff-турнир для пар, игроки регистрируются парами, и все видят турнирную сетку с результатами.

## v1 Requirements

Требования для первого релиза. Каждое маппится на фазу роадмапа.

### Authentication (AUTH)

- [ ] **AUTH-01**: Игрок регистрируется по email и паролю (Better Auth, hashing внутри библиотеки)
- [ ] **AUTH-02**: Игрок входит в систему, сессия сохраняется между визитами/перезагрузками
- [ ] **AUTH-03**: Игрок выходит из системы с любой страницы
- [ ] **AUTH-04**: Админ-аккаунт организации (роль `admin`) создаётся идемпотентным seed-скриптом из переменных окружения
- [ ] **AUTH-05**: Админ-only действия (создание турнира, старт, ввод/правка результатов) защищены проверкой роли на сервере (в Server Action), не только скрытием UI

### Player profile (PLAYER)

- [ ] **PLAYER-01**: При регистрации игрок указывает отображаемое имя и предпочитаемую сторону корта (левая / правая)
- [ ] **PLAYER-02**: Предпочитаемая сторона корта отображается в профиле и в списках участников (display-only, без логики в v1)

### Tournaments (TOUR)

- [ ] **TOUR-01**: Админ создаёт турнир: название, размер (4 / 8 / 16 пар), формат single-elimination (пары); опционально дата и место
- [ ] **TOUR-02**: Любой пользователь видит список турниров со статусом (регистрация открыта / идёт / завершён)
- [ ] **TOUR-03**: Любой пользователь видит страницу турнира: информация, список зарегистрированных пар, статус
- [ ] **TOUR-04**: Турнир имеет статусы `registration → in_progress → finished`; переходы выполняются серверными переходами с гвардами

### Registration / Pairs (REG)

- [ ] **REG-01**: Авторизованный игрок регистрируется на турнир (в статусе `registration`), выбирая партнёра из списка зарегистрированных пользователей → создаётся пара (`player1`, `player2`)
- [ ] **REG-02**: Система атомарно отклоняет некорректную регистрацию: партнёрство с самим собой, игрок уже состоит в паре этого турнира, превышение вместимости
- [ ] **REG-03**: Регистрация закрывается при достижении вместимости турнира (4 / 8 / 16 пар) — больше пар добавить нельзя

### Bracket (BRKT)

- [ ] **BRKT-01**: Админ нажимает «Старт» (при ровно 4/8/16 зарегистрированных парах) → генерируется полная single-elimination сетка случайной жеребьёвкой (Fisher–Yates), турнир переходит в `in_progress`
- [ ] **BRKT-02**: Любой пользователь видит турнирную сетку: раунды, матчи, пары, победители и ещё не определённые (TBD) слоты
- [ ] **BRKT-03**: После генерации сетка иммутабельна — нет повторной жеребьёвки

### Matches & results (MATCH)

- [ ] **MATCH-01**: Админ вводит счёт (строка) и победителя матча; победитель автоматически продвигается в следующий матч (слот A/B) в рамках транзакции
- [ ] **MATCH-02**: Когда у финального матча определён победитель → турнир переходит в `finished`, чемпион отображается на странице турнира
- [ ] **MATCH-03**: Админ может править ранее введённый результат в любой момент (победитель перезаписывается, обновляется слот следующего матча) — без дополнительных ограничений

## v2 Requirements

Отложено на будущее. Отслеживается, но не входит в текущий роадмап.

### Singles & formats

- **SING-01**: Турнир для одиночек со случайным подбором пары в зависимости от типа соревнования
- **FMT-01**: Другие форматы: round-robin, групповой этап, double-elimination
- **FMT-02**: Жеребьёвка с bye для числа пар, не являющегося степенью двойки

### Enhancements

- **RANK-01**: Рейтинги игроков / посев по рейтингу
- **NOTF-01**: Уведомления (email/in-app) о матчах и регистрации
- **PAIR-01**: Подтверждение партнёрства (mutual invite/accept)

## Out of Scope

Явно исключено. Зафиксировано для предотвращения расползания scope.

| Feature | Reason |
|---------|--------|
| Bye / число пар не степень двойки | Регистрация закрывается ровно на 4/8/16 — bye-логика не нужна |
| Email-верификация при регистрации | Нет SMTP/интернета на демо-машине; не нужно для диплома |
| Structured scoring engine (сеты/геймы/тай-брейк) | Счёт хранится строкой; источник истины продвижения — поле winner |
| Регистрация дополнительных админов / multi-admin | Организация — единственный админ (seed-аккаунт) |
| Мобильное приложение | Только веб |
| Оптимизация под нагрузку / кэширование / масштабирование | Диплом, реальной нагрузки нет |
