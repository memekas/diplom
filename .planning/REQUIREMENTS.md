# Requirements: Padel Tournaments — Milestone v2.0

**Defined:** 2026-06-07
**Core Value:** Организация создаёт турнир для пар/одиночек в одном из четырёх форматов, игроки регистрируются (по уровню), и все видят сетку/таблицу/standings с результатами по мере продвижения.

**Phase structure:** горизонтальные слои. Слой 1 (модель данных) → Слой 2 (бэкенд) → Слой 3 (фронтенд/UX). Порядок слоёв строгий; нумерация фаз продолжается с 7.

## Milestone v2.0 Requirements

Каждое требование маппится ровно на одну фазу (см. Traceability). Источник — бизнес-требования (Google Doc) + согласованные решения.

### Слой 1 — Модель данных (`DATA`)

- [ ] **DATA-01**: Уровень игры (`User.skillLevel`) обязателен при регистрации и принимает одно из пяти RU-значений (новичок / прогрессирующий / средний / высокий / профессиональный); добавлена опциональная дата рождения (`User.birthDate`).
- [ ] **DATA-02**: Модель `Tournament` хранит формат (`playoff` / `round_robin` / `americano` / `mexicano`), вид (`singles` / `pairs`), уровень участников (5 RU) и цену.
- [ ] **DATA-03**: Модель данных формата round-robin: матчи «каждый-с-каждым» + хранение результатов и очков для турнирной таблицы (standings).
- [ ] **DATA-04**: Модель данных форматов американо/мексикано: раунды с ротацией составов + индивидуальные очки каждого игрока.
- [ ] **DATA-05**: Участник турнира представлен как одиночный игрок ИЛИ пара (одиночная запись наряду с парной), без поломки существующих playoff-пар.
- [ ] **DATA-06**: Миграция БД (допустимы `migrate reset` + reseed) и сиды (`seed.ts`, `seed-test-users.ts`) обновлены под обязательный уровень (5 RU) и дату рождения.
- [ ] **DATA-07**: Режим подсчёта очков (`Tournament.scoringMode`: `sets` — геймы/сеты | `points` — просто очки); `setsPerMatch`/`gamesPerSet` настраиваемые без верхнего лимита; «очковый» результат хранится как произвольные целые на сторону (без границы).

### Слой 2 — Бэкенд (`TOUR` / `FMT` / `SCORE` / `REG` / `ADMN` / `USR`)

- [ ] **TOUR-05**: Админ создаёт турнир с новыми полями (формат, одиночный/парный, уровень, количество, цена); валидация количества участников зависит от формата (playoff — 4/8/16; round-robin/американо/мексикано — свободное число).
- [ ] **FMT-01**: При старте round-robin-турнира генерируется расписание «каждый-с-каждым».
- [ ] **FMT-02**: При старте/продвижении американо/мексикано система формирует и ротирует составы по раундам и накапливает индивидуальные очки игроков.
- [ ] **FMT-03**: Админ вводит результаты, после чего формируется следующий раунд / обновляется турнирная таблица (standings) — для каждого формата (playoff уже реализован).
- [ ] **SCORE-01**: Ввод и валидация результата ветвятся по режиму подсчёта: `sets` (произвольное число сетов и геймов, без лимита; правило победы сета обобщено под настраиваемый `gamesPerSet`) или `points` (два произвольных целых, победитель — у кого больше); победитель матча вычисляется по режиму.
- [ ] **REG-05**: При регистрации проверяется совпадение уровня игрока и уровня турнира (строгое равенство); запись на турнир не своего уровня отклоняется.
- [ ] **REG-06**: Одиночная регистрация для singles-турниров; для американо/мексикано регистрация только одиночная (партнёров назначает система).
- [ ] **ADMN-01**: Админ может удалить зарегистрированного участника/пару на этапе открытой регистрации.
- [ ] **ADMN-02**: Админ может вручную завершить турнир (для всех форматов).
- [ ] **USR-03**: Личный кабинет (сервис/действие) позволяет игроку править все свои поля профиля: ФИО, уровень, телефон, дату рождения, никнейм (с проверкой уникальности) и email (через флоу смены email Better Auth).

### Слой 3 — Фронтенд / UX (`SITE` / `HOME` / `HDR` / `FORM` / `SCORE` / `VIS`)

- [ ] **SITE-01**: Весь интерфейс на русском языке (`<html lang="ru">`), включая страницы входа/регистрации, dashboard, профиль, навигацию и подписи значений уровня.
- [ ] **SITE-02**: Принудительная тёмная тема на всём сайте (включая исправление захардкоженных светлых значков статуса/алертов).
- [ ] **SITE-03**: Адаптивная вёрстка под desktop и мобильные устройства.
- [ ] **HOME-01**: Главная страница показывает список открытых для регистрации турниров.
- [ ] **HDR-01**: Шапка сайта содержит название клуба, логотип, кнопку «Прошедшие турниры» и вход в личный кабинет.
- [ ] **FORM-01**: Форма создания турнира предоставляет поля: формат, одиночный/парный, уровень участников, количество, цена.
- [ ] **FORM-02**: Форма регистрации собирает обязательный уровень (5 RU) и дату рождения; UI поддерживает одиночную и парную (ник партнёра) запись по виду турнира.
- [ ] **FORM-03**: Расширенная форма ЛК (правка всех полей профиля) + админ-элементы управления: удаление зарегистрированной пары/участника и ручное завершение турнира.
- [ ] **SCORE-02**: Форма создания содержит селектор режима подсчёта и (для `sets`) поля числа сетов/геймов без верхнего предела; ввод результата админом ветвится по режиму (N сет-строк vs два поля очков); счёт визуализируется согласно режиму.
- [ ] **VIS-01**: Визуализация активного турнира по формату: playoff-сетка (есть), таблица round-robin, standings/раунды американо-мексикано; панели «текущие игры» и «прошедшие игры».
- [ ] **VIS-02**: Просмотр прошедших (завершённых) турниров с историей матчей согласно формату.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Жеребьёвка с bye для не-степени-двойки | playoff остаётся ровно 4/8/16; прочие форматы — свободное число |
| Групповой этап, double elimination | не входят в набор форматов v2.0 |
| Очки внутри гейма (15/30/40, advantage, golden point) | режим `points` считает произвольные целые на матч, не внутригеймовые теннисные очки |
| Глобальные рейтинги игроков между турнирами | есть только standings внутри турнира (американо/мексикано) |
| Онлайн-оплата | цена отображается, оплата производится в клубе (п.3.4.7) |
| Real-time через websockets | обновление через `revalidatePath` после действий админа достаточно для диплома |
| Push/email-уведомления | вне рамок дипломной работы |
| Мобильное приложение | только адаптивный веб |
| Нагрузочная оптимизация, кэширование, масштабирование | диплом, реальной нагрузки нет |
