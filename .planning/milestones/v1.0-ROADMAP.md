## Overview

Веб-приложение для организации single-elimination турниров по паделу (пары). От пустого
репозитория до рабочего приложения: аутентификация, управление турнирами, регистрация пар,
генерация турнирной сетки и ввод результатов по сетам с авто-продвижением победителей.
Стек: Next.js 16 (App Router, TS) + Prisma 6 (SQLite) + Better Auth ^1.6 + Tailwind 4, npm.

## Milestone Summary

**Key accomplishments:**
- Better Auth ^1.6 email/password + admin-role guards + idempotent env-seeded admin.
- Admin tournament CRUD (4/8/16) with a single guarded status state machine (registration→in_progress→finished).
- Transactional pair registration (no self-partner / no double-register / capacity-locked).
- Pre-generated immutable single-elimination bracket (Fisher–Yates, tested slot arithmetic) + public bracket view — the Core Value.
- Structured tennis scoring (sets→games, configurable counts fixed at 3/6 for v1) with derived winners, transactional auto-advancement, final→champion, and free editing.
- Quality: per-phase code review with fixes, ~115 unit/integration assertions across scoring/bracket/integrity, full cross-phase E2E verified, clean `next build`.

**Key decisions:** (see PROJECT.md Key Decisions)
- Better Auth over hand-rolled/Auth.js v5; npm; Prisma 6 (not 7); kysely pinned 0.28.17 (better-auth build fix); terminal status canonical "finished"; partner Variant B; structured sets/games scoring with future-configurable counts.

**Accepted limitations (out of scope — concurrency/load not required for a thesis):**
- registerPair capacity TOCTOU under true concurrency (SQLite single-writer mitigates).
- Result edit re-propagates only to the immediate parent (no downstream cascade cleanup).

**Pending (advisory):** Browser-only UAT per phase (`*-HUMAN-UAT.md`) — all logic proven via unit tests + e2e + clean build.
