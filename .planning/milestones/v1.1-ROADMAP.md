## Overview

Дополнение v1.0 MVP: у каждого игрока теперь есть уникальный никнейм, задаваемый при регистрации
(обязательное поле, гарантия уникальности на уровне БД `@@unique` + ветвление на `error.code`
при дубле). Запись на турнир переведена с выбора партнёра из выпадающего списка на ввод никнейма
с точным lookup (`findUserIdByNickname`), сохранив v1.0 транзакционную целостность `registerPair`.

**Success Criteria** (all TRUE):

3. На форме участия — текстовое поле ника партнёра, список не предлагается. ✅
4. Существующий ник → точный lookup → пара; несуществующий → ошибка, пара не создаётся. ✅

## Key Accomplishments

1. **`User.nickname` — обязательное уникальное поле** через Better Auth `additionalFields { required:true, input:true }` + `inferAdditionalFields<typeof auth>()` на клиенте для типизированного `signUp`; миграция `add_user_nickname` (`CREATE UNIQUE INDEX`).
2. **Атомарная обработка дубля ника** — форма ветвится на стабильном `error.code === "FAILED_TO_CREATE_USER"` (не на `error.message`), показывает RU-сообщение; signUp атомарен (нет orphan-строк).
3. **Запись по нику (REG-04)** — `<select>` → текстовое поле `player2Nickname`; `findUserIdByNickname` резолвит userId ДО нетронутого транзакционного `registerPair`; новый код ошибки `partner_not_found`; самопаринг по-прежнему ловится guard'ом `player1Id===player2Id`.
4. **Сид-бэкфилл** — админ (`admin`) + 20 тестовых игроков (`playerN`) с уникальными никами; `migrate reset` + `seed:test-users` → приложение работает из коробки.
