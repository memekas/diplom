<objective>
Drop the three functionally-dead scoring columns `setsPerMatch`, `gamesPerSet`,
`targetPoints` from `model Tournament`, unplumb every inert reference to them across
services / actions / forms / tests, run a Prisma migration + client regen, and sync the
data-model design doc (`docs/04-model-dannyh.md`).

These columns went dead with the free-form scoring change (STATE: [post-v2.0] Free-form
scoring): `result.ts` step (1) reads NO set/game config; `round-result.ts` points mode has
NO target. The columns survive only in `tournamentSelect`, as inert props threaded into the
two score forms, and as an untrusted `_setsPerMatch` param on `recordResultAction`. The
create zod schema already omits them.

Purpose: schema honesty — remove dead columns and the now-false "kept to avoid migration"
rationale; the thesis defense should not have to explain vestigial fields.
Output: a clean Tournament model, a `drop_legacy_scoring_columns` migration, regenerated
client, green test suite + build, and an accurate ch.2 data-model doc.
</objective>
