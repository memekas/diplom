# Quick Task 260608-sd2 — Документация проектирования (глава 2)

## Цель

Подготовить исчерпывающую проектную документацию по приложению «Padel Tournaments»
в каталоге `docs/` (на русском), пригодную как исходный материал для главы 2
«Проектирование» дипломной работы. Документы будут читать другие ИИ-агенты/диалоги
для написания связного текста главы. **Без написания кода** — только проектирование:
описания, схемы и диаграммы (Mermaid).

## Объём (deliverable)

Набор из 12 связанных Markdown-документов в `docs/`:

1. `README.md` — индекс/навигатор + соответствие главе 2.
2. `01-naznachenie-i-trebovaniya.md` — назначение, акторы, функциональные и нефункциональные требования, ограничения, вне scope.
3. `02-glossariy.md` — глоссарий предметной области (падел, форматы) и системы.
4. `03-arhitektura.md` — стек, App Router (RSC + Server Actions), слои, диаграмма компонентов, потоки данных, структура каталогов.
5. `04-model-dannyh.md` — ER-диаграмма, все 9 моделей, поля, связи, ограничения, нормализация, String-enum, аддитивность.
6. `05-formaty-i-algoritmy.md` — 4 формата и алгоритмы (bracket gen + advance, круговой, американо circle-on-players, мексикано по раундам), flowcharts.
7. `06-podschyot-i-standings.md` — режимы подсчёта (sets/points, free-form), вычисление победителя, рейтинги/таблицы, тай-брейкеры.
8. `07-stsenarii-ispolzovaniya.md` — use-case диаграмма + sequence-диаграммы основных сценариев.
9. `08-mashiny-sostoyaniy.md` — жизненные циклы (турнир, раунд, матч) + диаграммы состояний.
10. `09-polzovatelskiy-interfeys.md` — карта сайта, страницы, навигация, формы, компоненты визуализации, тёмная тема/адаптив.
11. `10-autentifikatsiya-i-bezopasnost.md` — Better Auth, роли, guards, модель угроз.
12. `11-servernye-deystviya-i-validatsiya.md` — server actions, zod-схемы, модель типизированных ошибок.

Общий бриф фактов: `.planning/quick/260608-sd2-comprehensive-design-documentation-for-t/FACTS.md`
(единый источник правды, все доки выверены по нему и по актуальному коду).

## Задачи

1. **Сбор и выверка фактов** — проанализировать `prisma/schema.prisma`, `src/lib/**`, `src/app/**`;
   составить `FACTS.md` (соглашения + проверенные факты + карта документов). ✅
2. **Spine-доки** — написать индекс (`README.md`), требования (`01`), модель данных (`04`) —
   несущая часть с точными ER/требованиями.
3. **Тематические доки** — написать `02,03,05,06,07,08,09,10,11`, каждый заземлён на реальные
   исходники и `FACTS.md`, с корректными Mermaid-диаграммами и кросс-ссылками.
