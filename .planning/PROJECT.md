# Padel Tournaments

## What This Is

Веб-приложение для организации турниров по паделу. Платформа делается для одной конкретной организации (клуб), которая выступает администратором: только она создаёт турниры. Игроки регистрируются (с уровнем игры), участвуют одиночно или парами, смотрят информацию о турнире и визуализацию результатов по формату. Поддерживаются четыре формата: Олимпийская (playoff), Раунд-робин, Американо, Мексикано — с настраиваемым режимом подсчёта (сеты/геймы или просто очки). Только русский язык, тёмная тема, адаптив.

Дипломная работа — не продакшн, реальной нагрузки не будет. Приоритет: простое работающее приложение, сделанное быстро, без усложнений и преждевременной оптимизации.

## Core Value

Организация может создать турнир любого из четырёх форматов (с матчингом по уровню и выбором режима подсчёта), игроки регистрируются одиночно или парами, и все могут видеть визуализацию турнира с результатами по мере продвижения, а также историю прошедших турниров.

### Out of Scope

- Жеребьёвка с bye для не-степени-двойки — playoff остаётся ровно 4/8/16 (round-robin/американо/мексикано — свободное число участников)
- Групповой этап и double elimination — не входят в набор форматов v2.0
- Очки внутри гейма (15/30/40, golden point, advantage) — режим `points` считает произвольные целые на матч, не теннисные внутригеймовые очки
- Глобальные рейтинги игроков между турнирами — есть только standings внутри турнира (американо/мексикано)
- Онлайн-оплата — цена отображается, оплата в клубе (п.3.4.7)
- Real-time через websockets — обновление через `revalidatePath` после действий админа
- Push/email-уведомления — вне рамок дипломной работы
- Мобильное приложение — только адаптивный веб
- Высоконагруженная оптимизация, кэширование, масштабирование — не требуется (диплом, нет реальной нагрузки)

## Context

- Дипломная работа. Не будет использоваться в реальной жизни. Цель — рабочая демонстрация, не продакшн-система.
- Заказчик — одна конкретная организация, проводящая турниры. Она же единственный администратор платформы.
- Падел как предметная область важен в основном для оформления; ключевая механика — пары (2 игрока) и playoff-сетка.
- Главный принцип: простота и скорость разработки важнее оптимальности и расширяемости.

## Constraints

- **Tech stack**: Next.js 16 (TypeScript, App Router) full-stack — Server Components (чтение) + Server Actions (запись), Prisma 6.x (≥6.2), SQLite — Один язык и один репозиторий, быстрый старт, удобный рендер сетки на фронте; выбрано в questioning
- **Auth-библиотека**: Better Auth `^1.6` (email+password, `admin()` plugin для роли, Prisma-адаптер, SQLite, Node runtime) — Живая поддерживаемая библиотека (research/AUTH.md); email-верификация выключена для офлайн-демо
- **Форматы**: 4 формата — Олимпийская (playoff: только 4/8/16, без bye), Раунд-робин, Американо, Мексикано (свободное число участников). Американо/мексикано — ротационные (одиночная регистрация, система ротирует пары, индивидуальные очки); playoff/round-robin — одиночные или парные. Реализовано в v2.0.
- **Scoring**: настраиваемый режим подсчёта на турнир (`scoringMode`): сеты/геймы ИЛИ просто очки. Ортогонален формату. **Free-form (2026-06-08):** любое число сетов, любые неотрицательные целые геймы за сет, очки = два произвольных целых — без лимитов и без `targetPoints`. Поля `setsPerMatch`/`gamesPerSet`/`targetPoints` убраны из формы создания и не читаются (колонки в БД остались с дефолтами, миграции не было). Победитель вычисляется по геймам/сетам; ничья допустима во всех форматах кроме playoff (там — типизированная RU-ошибка, без продвижения). Per-set детализация — только playoff.
- **Auth**: единственный админ — предзаданный seed-аккаунт с ролью `admin` (создаётся идемпотентно из env) — Организация одна, регистрация админов не нужна
- **Scope**: дипломная работа — Делать просто и быстро, без преждевременной оптимизации и лишних фич
